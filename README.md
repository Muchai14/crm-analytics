# CRM Sales Analytics

An end-to-end analytics project on synthetic Salesforce-style CRM data, built with **dbt + DuckDB**. It answers the four questions every sales leader asks: *Do we have enough pipeline? Who closes best? How long does it take? Which channels pay off?*

## Business questions answered

| Mart | Question |
|---|---|
| `mart_pipeline_coverage` | Do we have enough open pipeline to hit this quarter's quota? (3x is healthy) |
| `mart_win_rate` | Which reps, segments and deal sizes close best? |
| `mart_sales_cycle` | How long does it take to close, and do lost deals drag longer? |
| `mart_lead_conversion` | Which lead sources convert best and return the most pipeline per marketing dollar? |

Each mart has a worked example query in [`analyses/`](analyses/) (e.g. `channel_roi_ranking.sql`, `pipeline_coverage_gaps.sql`).

## Architecture

```
generate_data.py ──▶ seeds/*.csv ──▶ dbt seed ──▶ DuckDB (raw schema)
                                                  │
                        ┌─────────────────────────┴─────────────────────────┐
                        ▼                                                   ▼
              models/staging/  (views: cleaning, type casts, dedup)   int_opportunity_funnel
              stg_opportunities, stg_leads, stg_accounts, ...          (view: funnel state machine,
                        │                                              stage order, win flags,
                        └─────────────────────────┬──────────────────── deal-size bands, sales cycle)
                                                  ▼
                                        models/marts/ (tables)
                                        mart_pipeline_coverage
                                        mart_win_rate
                                        mart_sales_cycle
                                        mart_lead_conversion
```

- **staging** — one view per raw table: trims strings, casts dates/amounts, dedupes on natural keys.
- **intermediate** — `int_opportunity_funnel`: the funnel state machine. Adds stage ordering (Prospecting → Closed), `is_open` / `is_closed` / `is_won` flags, close quarter, deal-size bands and realized `sales_cycle_days` for closed deals.
- **marts** — four tables, one per business question, each with model + column documentation and 2–3 data tests (`not_null`, `unique`, `accepted_values`).

## Key metric definitions

- **Pipeline coverage** = open pipeline (sum of open opportunity amounts closing in the quarter) ÷ quota. Healthy ≈ 3.0.
- **Win rate** = won deals ÷ closed deals (Closed Won + Closed Lost).
- **Sales cycle** = `close_date − created_date` in days, measured on closed deals only.
- **Lead conversion rate** = converted leads ÷ all leads, by source and quarter.
- **Pipeline per dollar** = pipeline dollars created by converted leads ÷ marketing spend for that source and quarter.

## How to run

Requires Python 3.10+.

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# 1. Generate the synthetic dataset (~200 accounts, 1,500 opportunities,
#    3,000 leads, 5,000 activities, Jan 2024 – Sep 2026)
python generate_data.py

# 2. Load seeds, build models, run tests (DuckDB warehouse, no server needed)
dbt seed --profiles-dir .
dbt run --profiles-dir .
dbt test --profiles-dir .
# or all at once:
dbt build --profiles-dir .
```

`profiles.yml` points DuckDB at `./crm_analytics.duckdb` in the project root.

## Data

All data is **synthetic**, generated by [`generate_data.py`](generate_data.py) (Faker + a fixed random seed, so the dataset is reproducible). It mimics a B2B SaaS CRM:

- **200** accounts (SMB / Mid-Market / Enterprise), **548** contacts
- **1,500** opportunities with realistic funnel decay (win rate ≈ 38% of closed deals)
- **3,000** leads across 7 sources with source-dependent conversion rates; ~50% of opportunities trace back to a converted lead
- **5,010** sales activities, quarterly quotas and marketing spend through 2027-Q1

## Limitations

Honest simplifications, worth knowing before citing any number:

- **Stage history is a snapshot, not a true state machine.** Opportunities carry only their *current* stage — there is no stage-transition history table, so time-in-stage and funnel velocity can't be measured precisely.
- **Quotas are synthetic and segment-level.** Real quotas are set per rep/territory; coverage here is computed per segment, not per rep.
- **Marketing spend is a flat per-quarter assumption** per channel, not modeled from real campaigns.
- **Amounts and cycles are drawn from lognormal/uniform distributions** tuned to look plausible, not calibrated to any real company's benchmarks.
